## 流程一:订单审批工作流(Order Approval)
### 1.1 拓扑:
START → order_approval → final_process → END

### 1.2 数据流转图
```text
调用方
│ ① GET /interruptable/order/process?orderId=..&amount=..&threadId=..
▼
Controller.processOrder()
▼ 只做参数透传
Service.processOrder()
│  写入 initialState: {order_id, order_amount}
▼
orderApprovalCompiledGraph.stream(initialState, config)
│
▼ START
OrderApprovalNode.interrupt()   ◀── 闸机询问
│
├─ order_amount > 10000 ?
│     │ 否 ──────────────┐
│     ▼ 是               │
│  (暂停)               │
│  状态存入MemorySaver   │
│  SSE下发中断消息        │
│  ── 等待人工 ──        │
│     │                  │
│     │ ② POST /order/resume?approved=true/false&threadId=..
│     ▼                  │
│  interrupt() 再次被调用  │
│  读到feedback → 放行    │
▼                         ▼
OrderApprovalNode.apply()   OrderApprovalNode.apply()  (金额≤1万直接走)
│  写入 order_status / message / processed_time
▼
FinalProcessNode.apply()
│  写入 workflow_status / order_final_status / completed_time / summary
▼
END  ──►  SSE 下发 node_output(带完整 state)


```
### 1.3 逐环节数据写入/读取
```text
┌─────────────────────────────────────────────────────────────────┬───────────────────────────────────────┬───────────────────────────────────────────────────┐
│                            状态 key                             │               哪里写入                │                     哪里读取                      │
├─────────────────────────────────────────────────────────────────┼───────────────────────────────────────┼───────────────────────────────────────────────────┤
│ order_id                                                        │ 入口 initialState                     │ interrupt()、apply()、generateSummary()           │
├─────────────────────────────────────────────────────────────────┼───────────────────────────────────────┼───────────────────────────────────────────────────┤
│ order_amount                                                    │ 入口 initialState                     │ interrupt()(判断阈值)、apply()、generateSummary() │
├─────────────────────────────────────────────────────────────────┼───────────────────────────────────────┼───────────────────────────────────────────────────┤
│ approved                                                        │ resume 时经 STATE_UPDATE_METADATA_KEY │ apply()(分支判断)                                 │
├─────────────────────────────────────────────────────────────────┼───────────────────────────────────────┼───────────────────────────────────────────────────┤
│ order_status                                                    │ apply()                               │ FinalProcessNode、generateSummary()               │
├─────────────────────────────────────────────────────────────────┼───────────────────────────────────────┼───────────────────────────────────────────────────┤
│ message                                                         │ apply()                               │ 仅随 SSE 输出                                     │
├─────────────────────────────────────────────────────────────────┼───────────────────────────────────────┼───────────────────────────────────────────────────┤
│ processed_time                                                  │ apply()                               │ 仅随 SSE 输出                                     │
├─────────────────────────────────────────────────────────────────┼───────────────────────────────────────┼───────────────────────────────────────────────────┤
│ workflow_status / order_final_status / completed_time / summary │ FinalProcessNode                      │ 仅随 SSE 输出                                     │
└─────────────────────────────────────────────────────────────────┴───────────────────────────────────────┴───────────────────────────────────────────────────┘
```
### 1.4 关键分支逻辑

1. interrupt()(闸机):读 config 里的 HUMAN_FEEDBACK_METADATA_KEY。第一次调用时没有 feedback → 看金额。amount > 10000 就构造中断元数据(reason/order_id/order_amount/threshold/interrupt_time)返回 →
   流程暂停,SSE 下发 type: "interruption" 事件。金额在阈值内 → 直接放行。
2. resume:从 MemorySaver 取快照,把 approved 同时塞进 HUMAN_FEEDBACK_METADATA_KEY 和 STATE_UPDATE_METADATA_KEY(后者会把 approved 真正写进状态)。stream(null, resumeConfig) 从断点继续。
3. apply() 再判断:interrupt() 第二次调用时发现 feedback 已存在 → 放行进 apply。apply 读 approved:
   - approved=true → order_status = "approved_and_processing"
   - approved=false → order_status = "rejected"
   - 金额 ≤ 1万(未走中断)→ order_status = "processing"
4. FinalProcessNode:读 order_status,拼出 summary,写收尾字段,图结束。

数据流转一句话:order_id + order_amount 进 → 闸机按金额拦一道 → 人工用 approved 决定去向 → order_status 贯穿到 FinalProcessNode 生成汇总 → 完成。


## 流程二:敏感操作确认工作流(Sensitive Operation)

### 2.1 拓扑:
START → sensitive_operation → final_process → END

### 2.2 数据流转图
```text
调用方
│ ① POST /interruptable/operation/execute?operation=..&params=k:v,k:v&threadId=..
▼
Controller.executeSensitiveOperation() → Service
│  解析 params("k:v,k:v" → Map)
│  写入 initialState: {operation, operation_params}
▼
sensitiveOperationCompiledGraph.stream(initialState, config)
│
▼ START
SensitiveOperationNode.interrupt()   ◀── 闸机询问
│
├─ operation ∈ SENSITIVE_OPERATIONS ?  ──(delete_user / delete_database /
│     │ 否 ────────────────┐           modify_system_config / send_mass_email /
│     ▼ 是                 │           export_sensitive_data)
│  (暂停)                 │
│  状态存入MemorySaver     │
│  SSE下发确认消息          │
│  ── 等待人工 ──          │
│     │                    │
│     │ ② POST /operation/confirm?confirmed=true/false&threadId=..
│     ▼                    │
│  interrupt() 再次被调用   │
│  读到feedback → 放行      │
▼                          ▼
SensitiveOperationNode.apply()  SensitiveOperationNode.apply() (普通操作直接执行)
│  写入 status / result / error / executed_time
▼
FinalProcessNode.apply()
│  写入 workflow_status / operation_final_status / completed_time / summary
▼
END  ──►  SSE 下发 node_output


```
### 2.3 逐环节数据写入/读取
```text
┌─────────────────────────────────────────────────────────────────────┬─────────────────────────────────────┬───────────────────────────────────────────────────┐
│                              状态 key                               │              哪里写入               │                     哪里读取                      │
├─────────────────────────────────────────────────────────────────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ operation                                                           │ 入口 initialState                   │ interrupt()(敏感判断)、apply()、generateSummary() │     
├─────────────────────────────────────────────────────────────────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ operation_params                                                    │ 入口 initialState(字符串解析成 Map) │ interrupt()(生成确认消息)、apply()                │
├─────────────────────────────────────────────────────────────────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ status                                                              │ apply()(success/failed)             │ FinalProcessNode、generateSummary()               │
├─────────────────────────────────────────────────────────────────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ result                                                              │ apply() 成功时                      │ 仅随 SSE 输出                                     │
├─────────────────────────────────────────────────────────────────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ error                                                               │ apply() 异常时                      │ 仅随 SSE 输出                                     │
├─────────────────────────────────────────────────────────────────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ executed_time                                                       │ apply()                             │ 仅随 SSE 输出                                     │
├─────────────────────────────────────────────────────────────────────┼─────────────────────────────────────┼───────────────────────────────────────────────────┤
│ workflow_status / operation_final_status / completed_time / summary │ FinalProcessNode                    │ 仅随 SSE 输出                                     │
└─────────────────────────────────────────────────────────────────────┴─────────────────────────────────────┴───────────────────────────────────────────────────┘
```

### 2.4 关键分支逻辑

1. interrupt():第一次无 feedback → 判断 operation 是否命中敏感名单(SENSITIVE_OPERATIONS)。命中 →
   构造中断元数据(reason/operation/operation_params/confirm_message(完整警告文本)/risk_level/interrupt_time)返回 → 暂停。普通操作 → 放行直接执行。
2. resume 与订单流程不同:/operation/confirm 只塞 HUMAN_FEEDBACK_METADATA_KEY = {confirmed: true/false},没有 STATE_UPDATE —— confirmed 这个值不会写进状态。
3. apply() 执行真实操作:读 operation + operation_params,调用 performOperation() 模拟执行。成功 → status=success + result;异常 → status=failed + error。
4. FinalProcessNode:读 status,生成汇总,收尾。

数据流转一句话:operation + operation_params 进 → 闸机按敏感名单拦一道 → 人工 confirm 后放行 → apply() 真实执行并回写 status/result → FinalProcessNode 汇总 → 完成。
